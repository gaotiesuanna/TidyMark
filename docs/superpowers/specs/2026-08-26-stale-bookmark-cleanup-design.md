# 清理模式：长期未点击的收藏

日期：2026-08-26  
状态：设计已确认，待实现计划

## 背景

TidyMark 已有可选的 Chrome `history` 权限，并在看板「访问」栏读取浏览历史、按域名统计访问次数。清理模式目前支持重复书签、失效链接和空目录，但不能找出「收藏过、长期没有再点击」的具体地址。

本功能在现有清理模式中增加一个「长期未点击的收藏」分区，用浏览历史补充书签信息，并复用现有的删除、移动、快照和撤销机制。

## 已确认需求

- 入口：现有「清理模式」中的新分区。
- 操作：发现后可逐条选择「删除」或「移动到待清理文件夹」。
- 时间分组：三个互斥分组：
  - 3–6 个月未点击
  - 6–12 个月未点击
  - 1 年以上未点击
- 时间计算：按自然月，不按固定天数；界面显示本次扫描实际使用的截止日期。
- 范围：当前整理范围，即 store 中的 `checkedIds`。不得因为没有当前范围而自动扩大到全库。
- 多个范围根：每个范围根分别拥有一个「待清理」文件夹，收藏不跨根合并。
- 无访问记录：单独列出；默认不进入删除或移动选择，但用户可以主动选择处理。
- 默认选择：所有记录均不勾选。
- 布局：单表筛选，不采用每个时间分组各自展开的卡片布局。
- 权限：必须先解释，再由用户点击按钮申请 `history` 权限；页面加载和 React effect 不得申请。

## 非目标

- 不把无访问记录断言为「用户从未访问过」。Chrome 历史可能被清除，且查询结果存在返回上限。
- 不新增独立的历史清理模式或新的页面。
- 不改变现有重复项、失效链接、空目录的全库扫描语义。
- 不自动删除或自动移动任何过期收藏。
- 不建立本地长期历史索引；本功能以当前 Chrome 历史查询结果为准。
- 不修改看板现有的访问域名排行口径。

## 架构与数据流

### 范围与现有清理扫描的边界

现有 `cleanup_scan` 继续保持全库扫描，因为重复项需要跨文件夹比较。过期收藏是新请求，单独使用当前 `checkedIds` 作为范围。这样满足「当前整理范围」要求，同时不改变现有清理功能的行为。

清理页可以先显示现有清理扫描结果；历史分区在用户授权后再独立扫描。历史扫描完成后写入独立的历史清理状态，不重置重复项、失效链接和空目录的选择。

### 请求流程

1. 清理页加载时不申请历史权限。
2. 历史分区显示说明、当前范围摘要和「读取浏览记录」按钮。
3. 用户点击按钮后，侧栏在同一个点击手势内调用现有 `ensureHistoryPermission()`。
4. 权限成功后，侧栏发送新的 `cleanup_stale_scan` 请求，携带当前规范化后的范围根 ID。
5. 后台读取书签树和 Chrome 历史记录。
6. 核心纯函数完成 URL 归一化匹配、最新访问时间归并、自然月分组和 unknown 分组。
7. 结果返回侧栏，显示单表筛选和逐条操作选项。
8. 执行时将删除/移动选择合并进现有 `CleanupSelection`，由 `applyCleanup()` 统一执行、保存快照、报告跳过和支持撤销。

### 浏览器边界

在 `src/core/ports.ts` 增加历史读取 port，避免核心层直接依赖 Chrome API：

```ts
interface HistoryVisit {
  url: string
  lastVisitTime?: number
}

interface HistoryApi {
  search(): Promise<HistoryVisit[]>
}
```

`src/background/chrome-ports.ts` 负责调用 `chrome.history.search({ text: '', maxResults: 10000, startTime: 0 })` 并映射为核心层数据。现有看板使用的 `visitUrls()` 保持其按访问次数排行的职责不变；需要最后访问时间的历史清理不复用只含权重的 `WeightedUrl`。

## 核心数据与规则

### 纯函数分类

新增零浏览器依赖的核心模块 `src/core/stale.ts`：

```ts
export type StaleBucket =
  | 'threeToSixMonths'
  | 'sixToTwelveMonths'
  | 'overOneYear'
  | 'unknown'

export interface StaleBookmark {
  item: BookmarkItem
  bucket: StaleBucket
  lastVisitedAt?: number
}

export interface StaleScanResult {
  items: StaleBookmark[]
  scannedAt: number
  cutoff3Months: number
  cutoff6Months: number
  cutoff12Months: number
}
```

函数输入为当前范围内的 `BookmarkItem[]`、历史访问记录和扫描时刻；函数不修改输入数组或节点。

### URL 匹配

- 书签 URL 和历史 URL 均使用现有 `normalizeUrl()`。
- 现有规则保持不变：去片段、去末尾路径斜杠、去追踪参数；不统一 `http`/`https`、`www` 或非白名单参数。
- 相同归一化 URL 的多条历史记录取最新 `lastVisitTime`。
- 找不到匹配，或匹配记录没有 `lastVisitTime`，归入 `unknown`。
- unknown 的界面文案必须说明「当前历史查询没有可用匹配」，不能写成「从未访问」。

### 自然月阈值

以扫描时刻的本地日历日期向前推 3、6、12 个自然月。界面显示这三个实际截止日期。

分组互斥，边界归入更老档位：

- `threeToSixMonths`：最后访问时间早于或等于 3 个月截止日，且晚于 6 个月截止日。
- `sixToTwelveMonths`：最后访问时间早于或等于 6 个月截止日，且晚于 12 个月截止日。
- `overOneYear`：最后访问时间早于或等于 12 个月截止日。
- 只要有可用的最后访问时间且比 3 个月更新，就不进入历史清理名单。
- 恰好落在某个截止日的记录进入更老的分组，避免同一记录同时出现在两个标签。

自然月计算需要明确处理月末日期，采用项目统一的本地日期格式化方式；测试覆盖跨年和二月等边界。

## UI

只改现有清理页及其 store / 消息契约，不新增页面。

### 分区状态

「长期未点击的收藏」分区显示在清理页现有分区中，与重复项、失效链接、空目录并列。

状态如下：

- `idle`：解释用途、显示当前范围、显示授权按钮。
- `loading`：显示历史读取中，不重复申请权限。
- `denied`：显示权限被拒绝和重试入口。
- `error`：显示查询失败和重试入口；不展示不完整名单。
- `ready`：显示结果、截止日期和筛选表。
- `empty`：当前范围没有可展示的过期记录；仍可查看无访问记录筛选项。
- 无当前范围：提示先在整理范围页选择文件夹，不发送全库历史扫描。

### 单表筛选

表头显示当前范围、扫描时间和三个截止日期。筛选标签为：

```text
全部 | 3–6 个月 | 6–12 个月 | 1 年以上 | 无访问记录
```

每行显示：

- 删除复选框
- 移动复选框
- 收藏标题
- 完整 URL
- 原书签路径
- 最后访问日期；unknown 显示「无可用访问记录」
- 时间档位

所有复选框初始不选中。删除与移动互斥，沿用现有失效链接分区的两个复选框交互和状态集合。unknown 行也可以被主动选择，但不会因为分类结果自动进入执行名单。

### 执行汇总

现有清理页底部吸底执行区域继续使用。历史分区选择的删除和移动数量加入统一的执行数量；没有任何选择时按钮保持禁用。现有撤销覆盖警告保持不变。

当前书签树或 `checkedIds` 变化后，历史名单被视为过期并清空，需要重新扫描；异步响应使用现有 `runSeq` 机制，不能写回已放弃的扫描轮次。

## 移动到「待清理」

- 移动目标是每个当前范围根的直接子目录。
- 目录标题跟随界面语言本地化。
- 目标根下已有同名直接子目录时复用；没有时创建一个。
- 多个范围根各自复用或创建一个目标目录，不将书签跨根合并。
- 目标目录创建或单条移动失败时，沿用现有清理引擎的部分成功和跳过记录语义。
- 被移动书签进入快照；撤销时恢复原父目录和原索引。

## 错误处理与安全

### 权限和历史查询

- 权限请求只发生在用户点击授权按钮的调用链中。
- 用户拒绝时不把拒绝当成空结果。
- 查询抛错时不把部分结果当成完整名单；显示错误和重试。
- Chrome 查询没有返回某 URL 时归入 unknown，并在说明中提示历史可能已清除或查询受限。

### 执行阶段

- 扫描后书签被删除或移动时，执行阶段逐条确认存在；不存在的条目进入跳过列表。
- 删除、移动和必要的目标文件夹创建使用现有 `applyCleanup()` 的快照、进度和撤销机制。
- 部分失败必须保留已成功删除/移动的计数和失败原因，不能假报整体成功。
- 历史名单不会覆盖重复项、失效链接、空目录的选择状态。

## 测试

### `tests/core/stale.test.ts`

覆盖：

1. 自然月阈值正确计算，包含跨年、二月和月末日期。

3. 三个时间分组互斥。
4. 最后访问时间不足 3 个月的书签不进入结果。
5. 同一归一化 URL 的多条历史记录取最新时间。
6. 现有 `normalizeUrl()` 规则用于匹配，白名单外参数不被错误剥除。
7. 无匹配或缺少 `lastVisitTime` 进入 unknown。

## 验收标准

- 未点击历史权限按钮时，Chrome 不弹出权限请求。
- 获得权限后，只显示当前整理范围内的过期收藏。
- 三个时间标签互斥，按照自然月和扫描时刻的截止日期归类。
- 无访问记录单独展示且默认不勾选。
- 用户可以逐条选择删除或移动；两种操作不能同时选择同一条。
- 多个范围根各自保留一个「待清理」目标目录。
- 执行、部分失败、快照和撤销与现有清理模式一致。
- 现有重复项、失效链接、空目录清理行为不改变。
